# `@synterai/mcp-server` (v1.4.7) — Technical Reference

- **Package**: `@synterai/mcp-server@1.4.7` (MIT license, [source](https://github.com/Synter-Media-AI/mcp-server))
- **Hosted MCP Endpoint**: `https://mcp.synterai.com` (Streamable HTTP + OAuth 2.1 with PKCE, or `X-Synter-Key` header for headless/CI clients)
- **Local Stdio Launch**: `npx -y @synterai/mcp-server@1.4.7` (pass `--read-only` to strip mutating tools from `tools/list` at startup, or `--demo` for offline schema/mock testing)

## 3. Authentication, Scoped Keys & Multi-Tenant Architecture (`docs.synterai.com/api/multi-tenant-auth`)

- **Hosted OAuth 2.1 (`https://mcp.synterai.com`)**: Uses OAuth 2.1 with dynamic client registration and PKCE for interactive coding agents (`claude mcp add --transport http --scope user synter-ads https://mcp.synterai.com` or `codex mcp add synter-ads --url https://mcp.synterai.com`). Unauthenticated HTTP requests to `https://mcp.synterai.com` return `401` with `WWW-Authenticate` metadata to initiate the MCP client's OAuth handshake.
- **Server-Side Scoped API Keys & Read-Only Enforcement**: Headless/CI services authenticate via `X-Synter-Key` or `Authorization: Bearer syn_...` (`SYNTER_API_KEY` in stdio). Server-enforced API keys minted via `POST https://synterai.com/api/v1/keys` support granular scopes (`reporting:read`, `campaigns:read`, `intel:read`), directional `budget:decrease` (allows emergency pauses and budget reductions while rejecting budget increases with `403`), or write scopes (`campaigns:write`, `budget:write`). Passing `--read-only` or `SYNTER_READ_ONLY=true` to `@synterai/mcp-server` also strips mutating tools from `tools/list` locally.
- **Multi-Tenant & Embedded SaaS Integration (Two Supported Patterns)**:
  1. **Hosted Workspace-Isolated Keys & Connect Links**: On the hosted platform, tenant data is isolated by **workspace**. Create a workspace per client in the web UI, mint workspace-pinned, least-privilege child keys via `POST https://synterai.com/api/v1/keys` (`scopes`, `rate_limit_rpm`, `expires_in_days`), and generate single-use advertiser OAuth handoff links via `POST https://synterai.com/api/v1/connections/start` (returns a single-platform `authUrl`) or `POST https://synterai.com/api/v1/connections/request` (emails a 7-day multi-platform connection link to the client). Switch workspaces on multi-workspace keys via `get_workspaces` and `update_active_workspace`. *(Note: programmatic workspace creation via `POST /api/v1/workspaces` and white-label multi-customer OAuth under a single shared key are not supported on the hosted service.)*
  2. **Self-Hosted / Embedded BYO-Credential Execution (MIT Open-Source)**: SaaS products that manage per-tenant OAuth apps and store customer tokens in their own vault can run `@synterai/mcp-server` or `synter` CLI (MIT license) as a local worker/subprocess and pass each tenant's decrypted platform credentials per invocation via environment variables (`GOOGLE_ADS_REFRESH_TOKEN`, `GOOGLE_ADS_CLIENT_ID`, `GOOGLE_ADS_CLIENT_SECRET`, `GOOGLE_ADS_DEVELOPER_TOKEN`, `META_ACCESS_TOKEN`, `LINKEDIN_ACCESS_TOKEN`, etc.) without routing credentials through Synter's hosted cloud.

## 4. Write Safeguards, Dry-Run Previews & Post-Write Readback

- **Schema & Policy Previews (`dry_run: true`)**: Campaign creation, `pause_campaign`, `update_campaign_budget`, and `add_negative_keywords` accept `dry_run: true` (`$0.00`) to validate arguments and inspect the planned payload without mutating live accounts.
- **Sandbox vs. Live Verification**: When `@synterai/mcp-server` runs without `SYNTER_API_KEY` (or with `--demo`), read tools and `dry_run: true` calls return deterministic synthetic responses (`sandbox: true`, `simulated: true`) for offline schema/integration testing. Before executing a live mutation, verify active platform connections via `get_connection_status` / `list_ad_accounts`, confirm workspace scope via `get_workspaces`, and verify every live mutation afterward via `get_ad_readback`, `get_campaign_observation`, or `list_campaigns`.

## 5. Coding Agent Tool Routing, REST Contract & Parameter Reference

Always call dedicated first-class read tools instead of routing read operations through `execute` / `run_action`:

| Task | Canonical Tool / Endpoint | Exact Parameters & Response Contract |
| :--- | :--- | :--- |
| **Canonical REST Tool Execution** | `POST https://synterai.com/api/v1/tools/run` | Headers: `Authorization: Bearer <SYNTER_API_KEY>` (or `X-Synter-Key: <SYNTER_API_KEY>`), `Content-Type: application/json`. Body: `{"script_name": "<tool_or_script>", "args": ["--flag", "value"], "platform": "GOOGLE"}`. |
| **HTTP Error & Rate-Limit Contract** | `401` / `402` / `429` | `401`: invalid/missing `SYNTER_API_KEY`. `402`: billing/credit wall (`error: "INSUFFICIENT_CREDITS"` or `"ACCOUNT_READ_ONLY"`, `upgradeUrl: "https://synterai.com/settings/billing?..."`). `429`: rate-limited (`Retry-After` header in seconds + `retry_after_seconds` in JSON body). |
| **Google Ads Custom GAQL Queries** | `run_gaql_query` (`$0.00`) | `{ query: "SELECT ...", customer_id?: "1234567890" }` (returns `{ success: true, rows: [...] }`; do **not** route GAQL `SELECT` queries through `execute`). |
| **Google Ads Search Terms & Keyword Hygiene** | `pull_google_ads_performance` / `add_negative_keywords` / `execute` | Read search terms via `run_gaql_query` (`FROM search_term_view`) or `execute(action="pull_google_ads", args=["--level", "search-terms", "--days", "14"])`. Add negatives via `add_negative_keywords({ campaign_id, keywords: [...], match_type: "EXACT" \| "PHRASE" \| "BROAD", dry_run?: true })`. Pause/enable keywords via `execute(action="google_ads_update_keywords", args=["--campaign-id", "<id>", "--ad-group-id", "<id>", "--criterion-id", "<id>", "--status", "PAUSED", "--dry-run"])`. |
| **StackAdapt & LinkedIn ABM Launch + Pixel Gate** | `get_pixel_health` / `linkedin_ads_create_campaign` / `execute` | Verify pixel attachment first via `get_pixel_health({ domain: "example.com" })` (returns `{ success: true, healthy: true, pixels: [{ platform, pixel_id, status, attached }] }`). Create PAUSED LinkedIn campaigns via `linkedin_ads_create_campaign({ account_id, name, daily_budget, status: "PAUSED", dry_run: true })` (or `execute(action="linkedin_ads_create_campaign_complete", args=["--account-id", "<id>", "--group-id", "<group_id>", "--name", "<name>", "--daily-budget", "100", "--status", "PAUSED", "--dry-run"])`). Stage PAUSED StackAdapt campaigns via `execute(action="create_stackadapt_campaign", args=["--advertiser-id", "<id>", "--name", "<name>", "--budget", "1000", "--status", "PAUSED", "--dry-run"])`. |
| **Post-Write Ground-Truth Readback** | `get_ad_readback`, `get_campaign_observation` (`$0.00`) | `{ platform: "google" \| "meta" \| "linkedin" \| ..., campaign_id: "...", customer_id?: "..." }` (use `customer_id`, not `account_id`, on Google Ads readback tools). |
| **Runtime Pricing & Credit Balance** | `get_solo_price_card`, `get_credit_balance` (`$0.00`) | `{}` — returns exact USD per-tool rates and remaining workspace USD balance. |
| **LLM & Coding-Agent Visibility Reads** | `get_llm_visibility_overview`, `get_coding_agent_visibility` (`$0.00`) | `{ project_id?: "..." }` — cardless `$0.00` read tools; never require a payment method on file. |
| **Generic Script Dispatcher (Mutations / Long-Tail)** | `execute` / `run_action` | Use `action` (or `script_name` on `/api/v1/tools/run`) for long-tail platform scripts (`"sa360_get_campaigns"`, `"dv360_create_campaign"`). Call `inspect_script({ script_name: "..." })` first if flag names are unknown. |
